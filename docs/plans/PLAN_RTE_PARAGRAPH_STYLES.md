# План: стили абзаца в редакторе форматированного текста

Статус: согласован 2026-11-12; Э1-Э4 и Э6 сделаны в ветке `feat/rte-paragraph-styles`, Э5 сделан для
шаблона `default`, перенос в `certification` и `standard-rt` ждёт разрешения.

## Источники

- Утверждённый эскиз: [rte-paragraph-styles.html](../wireframes/approved/rte-paragraph-styles.html).
- Карточки состояний:
  [2026-11-12-rte-paragraph-styles-wireframe-states.md](../specs/2026-11-12-rte-paragraph-styles-wireframe-states.md).
- Решения владельца: три уровня заголовков, крупный и мелкий текст, функция в компоненте ui-kit.
- Открытые вопросы эскиза закрыты предложениями из него: пункты меню без собственного вида;
  диалог ссылки модалки сохраняется через свойство компонента; плашка заголовка — забота
  шаблона РТК, вне этого трека.

## Модель

| Стиль в интерфейсе | Разметка |
| --- | --- |
| Обычный текст | `<p>` |
| Заголовок 1 | `<h2>` |
| Заголовок 2 | `<h3>` |
| Заголовок 3 | `<h4>` |
| Крупный текст | `<p class="tb-text-l">` |
| Мелкий текст | `<p class="tb-text-s">` |

Компонент ui-kit не знает ни подписей, ни классов `tb-*`: список стилей ему передаёт продукт
одной константой. Хранимые значения и формат `feedback_json.format` не меняются, миграций БД
нет, `richTextToHtml` не меняется.

## Где включается

- Модалка `FeedbackEditorModal` — все её места вызова: обратная связь теста, тем, уровней,
  толкование шкал, исходы показателей, вводные блоки итогов и отчёта.
- Поле «Описание» теста (`basic-settings-section.tsx`).
- Поля контентных страниц (`placeholder-control.tsx`) — НЕ включается: заголовок и вводный
  абзац там — отдельные поля макета, и стиль абзаца внутри них спорит с макетом. Включить
  позже можно одной строкой, если понадобится.

## Этапы

### Э1. Компонент `RichTextEditor` (ui-kit)

Файлы: `vendor/ui-kit/src/components/RichTextEditor.tsx`, CSS компонента во всех трёх копиях
ДС (`vendor/ui-kit/css/skillum-ds.css`, `client/src/styles/vendor/skillum-ds.css`,
`docs/wireframes/ds/skillum-ds.css`), история в Storybook.

1. Свойство `blockStyles?: RichTextBlockStyle[]`, где стиль — `{ id, label, tag, className?,
   shortcut? }`. Без свойства панель прежняя.
2. Список «Стиль абзаца» — DS `Select` `size="s"` первым в `ou-rte__tools`, за ним
   разделитель. Значение — стиль блока под курсором; пустое, если выделение захватывает
   разные стили; недоступен, когда курсор в пункте списка.
3. Применение — одна операция для всех шести стилей (подробно — в разделе «Решения по
   рискам», Р1):
   - выделение запоминается текстовыми смещениями от начала поля при каждом его изменении
     внутри поля — фокус уходит в список, и браузерный `Range` теряется;
   - на копии содержимого затронутые блоки верхнего уровня заменяются точно: тег и класс
     стиля, содержимое блока без изменений; пункты списков не трогаются;
   - содержимое поля целиком заменяется одной командой `execCommand('insertHTML')` — это
     ровно один шаг в стеке отмены браузера;
   - выделение восстанавливается по смещениям, фокус возвращается в поле, затем
     `onChange(clean(innerHTML))`.
   `execCommand('formatBlock')` не используется: он склеивает несколько абзацев в один.
4. На фокусе поля — `execCommand('defaultParagraphSeparator', false, 'p')`: иначе Chromium
   делит строки элементами `div`, а не абзацами, и стилю не к чему привязаться. Свободный текст
   и `div` верхнего уровня, если они уже есть в значении, при применении стиля оборачиваются
   в абзац.
5. Клавиши `Ctrl+Alt+0..3` в `onKeyDown` области ввода — по полю `shortcut` стиля.
6. Свойство `onRequestLink?: (selectedText) => Promise<{ url, text } | null>`. Без него —
   прежний `window.prompt`. Вставка ссылки идёт той же заменой через `insertHTML`, поэтому
   тоже отменяется `Ctrl+Z` (сегодня ссылка из диалога модалки ставится `insertNode` и не
   отменяется).
7. CSS области ввода — дельта компонента из эскиза (`h2`/`h3`/`h4` и два размера на токенах),
   минимальная ширина списка.
8. `Select` получает свойство `portal` (Р2); в панели редактора оно включено.
9. Тесты компонента (jsdom): список рисуется только со свойством; выбор стиля меняет тег и
   класс ровно у затронутых блоков; несколько абзацев остаются отдельными; клавиши; пустое
   значение при смешанном выделении; `onRequestLink` вызывается вместо `prompt`. Тесты
   `Select`: меню в портале, клик по пункту не закрывает меню раньше выбора, переворот вверх.
   Отмену jsdom не умеет — она проверяется в браузере (раздел «Проверки»).

## Решения по рискам

Оба решения проверены в Chromium 2026-11-12 одноразовыми страницами через Playwright; код
продукта не менялся.

### Р1. Отмена `Ctrl+Z` для стилей

Что не работает:

- класс, поставленный прямой правкой DOM, в стек отмены браузера не попадает;
- `insertHTML` одного блока: Chromium сливает новый абзац со следующим и теряет класс —
  `<p>…жирный</b>Второй абзац</p>`, класса нет;
- `formatBlock`: отменяется, но при выделении нескольких абзацев склеивает их в один —
  `<h2>Первый<br>Второй<br>Третий</h2>` — и оборачивает список целиком в заголовок.

Что работает: точное преобразование на копии и замена всего содержимого поля одной командой
`insertHTML`. Проверено: результат совпадает с ожидаемым побайтно (классы, ссылки, жирный,
`&nbsp;`, `&amp;`, пустой абзац сохранены); первый `Ctrl+Z` снимает стиль, второй — набранный до
этого текст; `Ctrl+Y` дважды возвращает всё; курсор после замены восстанавливается по текстовому
смещению в тот же символ.

Ограничение: проверено только в Chromium — на машине нет других движков, а их установка —
новая зависимость. Firefox поддерживает `insertHTML` так же, но без проверки я это не утверждаю.

### Р2. Обрезанное меню списка

`Select` из ui-kit рисует меню в потоке (`position: absolute` внутри поля), поэтому меню
обрезает любой прокручиваемый предок: в эскизе его обрезал `.tb-settings-content` с
`overflow-y: auto`. Отступить на `MenuTrigger` (он уже рисуется в портале) нельзя: у него другой
вид меню — галочка вместо выделенной строки, — а это расхождение с утверждённым эскизом.

Решение — свойство `portal` у `Select`, по умолчанию выключено, остальные `Select` продукта не
меняются:

- то же меню `ou-select__menu` с той же разметкой рисуется через `createPortal` в
  `document.body`, как `Popover` и `MenuTrigger`, со слоем `z-index: 1000` (поверх модалки и
  ящика, которые на том же слое, но раньше в документе);
- положение и ширина берутся от кнопки списка и пересчитываются на прокрутку и изменение
  размера окна; если снизу не хватает места, а сверху хватает — меню открывается вверх, как
  `Popover`;
- закрытие по клику снаружи учитывает и обёртку, и меню в портале — иначе клик по пункту
  закрыл бы меню до выбора;
- кнопки и пункты списка в панели редактора гасят `mousedown`, как кнопки панели сегодня, чтобы
  выделение в поле не терялось при клике мышью.

### Э2. Очистка вставки (`rte-paste.ts`)

1. `sanitizePastedHtml`: `H1`, `H2` → `h2`; `H3` → `h3`; `H4`–`H6` → `h4`; у `P` сохраняются
   только классы `tb-text-l` и `tb-text-s`.
2. `stripPastedPresentation` не меняется: заголовки он и так сохраняет.
3. Тесты в `rte-paste.test.ts`.

### Э3. Модалка `FeedbackEditorModal` на компоненте

1. Самодельные панель и `contenteditable` заменяются на `RichTextEditor` со всеми тремя
   режимами; строка «Формат» убирается. Соответствие режимов: `plain` ↔ `plain`,
   `rich` ↔ `richText`, `html` ↔ `html`.
2. `sourceMode` с `toMarkup` (абзацы из строк) и `toPlain` (`richTextToPlain`): простой текст
   хранится, как сегодня, — исходником с переводами строк. Изменение поведения: сегодня
   смена формата текст не трогает, после — переводит его, без потери абзацев.
3. `transformPaste={sanitizePastedHtml}` — та же строгая очистка, что сегодня.
4. Диалог «Вставить ссылку» передаётся через `onRequestLink`.
5. Подпись поля — `textLabel`, как сегодня.
6. Тесты: `feedback-editor-modal.test.tsx` и `.coverage.test.tsx` держатся за `rte-bold`,
   `rte-link`, `feedback-editor-rte-area`, `feedback-editor-text`; переписываются на
   идентификаторы компонента. Плюс семь наборов вызывающих сторон, которые ищут те же
   идентификаторы (`band-`, `breakdown-`, `level-`, `topic-feedback-card`,
   `topics-structure-section`, `topic-drawer`, `basic-settings-section.coverage`).
7. Стили `tb-rte*` из `tb-components.css` удаляются, если других потребителей не останется.

`blockStyles` в `basic-settings-section.tsx`; константа стилей — одна, рядом с `rte-paste.ts`.

### Э5. Шаблоны

1. `server/scorm/templates/default/styles/theme.css`: дельта шаблона из эскиза — общий набор

   `.tb-topic-group__description`, `.tb-measure .ou-banner__desc` и описание шкалы.
2. `report.css`: тот же набор для `.tb-report__intro`, `.tb-report__scale-text`,
   `.tb-report__event`, `.tb-report__topic-group-description`.
3. `results.html` и `results.adaptive.html`: `<p class="ou-formsection__sub">{{& textHtml }}</p>`
   → `<div class="ou-formsection__sub">`.
4. Версия `manifest.json` шаблона `default` поднимается.
5. Контракт шаблонов, минор: в спецификацию платформы шаблонов и руководство разработчика
   шаблонов — раздел «Авторский текст» (уровни `h2`–`h4`, классы `tb-text-l`/`tb-text-s`);
   версия в спеке и в трёх местах руководства; `npm run docs:pdf` с возвратом чужих PDF.
   Перед бампом — сверка версии на `main`.
6. Шаблоны `certification` и `standard-rt` в своих репозиториях — те же правила, подъём
   версии манифеста, тег. Это отдельные коммиты в отдельных репозиториях; делаю по вашему

## Проверки

- Целевые прогоны: `npm test -- <путь>` по затронутым наборам; полный прогон и `test:cov` — только
  по вашему разрешению.
- `npm run check`, `npm run lint:md`.
- Приёмка в браузере (Playwright): каждое состояние эскиза против реализации, бок о бок
  скриншотами — поле «Описание», модалка, режим HTML, экран итогов в web-хосте; тёмная тема.
- SCORM: `npm run scorm:template` с текстом из эскиза — заголовки и размеры в пакете и в отчёте
  PDF выглядят так же, как в web.

разрешению. Новых зависимостей нет.
