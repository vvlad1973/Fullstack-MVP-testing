# План: содержимое блока отчёта по исходу теста

Эскиз (согласован 2026-11-12):
[approved/report-block-outcome.html](../wireframes/approved/report-block-outcome.html).
Карточки состояний:
[report-block-outcome/wireframe-states.md](../specs/report-block-outcome/wireframe-states.md).

**Цель.** Автор задаёт блоку документа отчёта разное содержимое для прошедшего и для не
прошедшего тест, по образцу вводного текста экрана итогов. Шаблон объявляет, какие поля и
настройки есть у блока, и может дать им умолчания по исходу.

**Новых зависимостей нет.**

## Правила (согласованы)

| Что | При вынесенном вердикте |
| --- | --- |
| Длинный текст (поле `html`) | Общий текст, следом текст исхода. Пустой общий — только текст исхода. Пустой текст исхода — ничего не дописывается. |
| Короткое поле (`text`) | Значение исхода заменяет общее; не задано — общее. |
| Настройка блока | Как короткое поле. |

- Вердикт не вынесен (нет порога, нечего оценивать, адаптивный режим) — печатается только
  общее. Признак — `hasPronouncedVerdict()` из `shared/scoring/pass-rule`, тот же, что гасит
  вердиктную шапку. Второго определения не заводим.
- Тумблер включения блока не меняется. Один системный блок — не больше одного раза в документе.
- Значения исхода, заданные до того, как у теста убрали порог, хранятся и не печатаются.

## Этапы

### Э1. Данные

- `shared/schema.ts`: колонка `report_blocks.outcome_json`, jsonb, NOT NULL, умолчание `{}`.
  Форма: `{ passed?: { values?, settings? }, failed?: { values?, settings? } }`.
- Миграция `drizzle/0065_*` (генерируется `drizzle-kit generate`), только добавляет колонку —
  `predev` применит её сам.
- Репозиторий `server/storage/report-blocks-repository.ts`: колонка в whitelist записи.
- `server/routes/tests.ts`: `reportBlockBodySchema` принимает `outcomeJson` той же формы;
  чужие ключи (не `passed`/`failed`, не `values`/`settings`) отбрасываются.
- Снимок публикации (`server/services/test-snapshot.ts`) хранит строку целиком — колонка
  попадает в него сама; проверить тестом, что снимок её несёт и дрейф её видит.
- Перенос и копирование теста, книга Excel (PRD-14), если они переносят `report_blocks`, —
  проверить и провести колонку там же.
- Снимок схемы pglite для `npm run test:it` — обновить.

**Тесты:** запись и чтение колонки (it на pglite), валидация тела маршрута, снимок.

### Э2. Правило печати в `shared/report`

- `report-document.ts`: `ReportBlockRowInput` и `ResolvedReportBlock` получают `outcome`.
- Новая чистая функция `applyOutcome(blocks, outcome, placeholders)` рядом с
  `resolveReportDocument`: по исходу накладывает значения на общие по таблице правил выше.
  Тип поля берётся из `placeholders[]` варианта; для `html` склейка через тот же порядок, что
  в `introBlocksToPrint` (`report-intro.ts`).
- Вызывается в одном месте — `exportReportPdf` (`export-pdf.ts`) перед `renderReportInto`;
  `ReportPage` получает поле исхода `{ verdictPronounced, passed }`. Так правило одно для веб-PDF
  (`client/src/features/learner/attempt-report.ts`), пакета
  (`server/scorm/template/app/utils/pdfExport.js`) и предпросмотра
  (`report-preview-modal.tsx`, переключатель «Пройден / Не пройден» уже есть).
- Настройки блока сейчас до раскладки не доходят: `renderReportInto` передаёт только
  `placeholders` и `values`. Передать и разрешённые `settings` блока, чтобы шаблон мог их
  читать (форма — в Э3).
- Пакет: `server/scorm/builders/test-json.ts` запекает `outcome` строк вместе с остальным
  документом.

**Тесты:** таблица правил по каждому типу поля и исходу; вердикт не вынесен; пустые значения;
пакет запекает колонку; предпросмотр показывает разные документы по переключателю.

### Э3. Контракт шаблона и стандартный шаблон

- Вариант блока `report.block` в манифесте: у поля (`placeholders[]`) и настройки
  (`settings[]`) необязательное `outcomeDefaults: { passed?, failed? }`.
- Валидатор манифеста (`server/services/template-validation.ts`) принимает и проверяет его.
- Редактор берёт умолчания исхода из варианта, пока строка своих не задала.
- Стандартный шаблон (`server/scorm/templates/default/`): объявить поля у системных блоков —
  состав см. «Решения до старта», вопрос 1.
- Контракт 3.20.0 → 3.21.0 (минор: только добавления). Двигаются вместе:
  `docs/specs/spec-template-platform.md` (версия, история, раздел про блоки отчёта),
  `docs/guides/template-development.md`, PDF документации (`npm run docs:pdf`) и остальные
  места, где записана версия контракта.

**Тесты:** валидатор; разрешение умолчаний; стандартный шаблон печатает прежний документ,
пока поля пусты.

### Э4. Редактор

По эскизу узел в узел, состояния s-list, s-common, s-outcome, s-outcome-off, s-no-verdict.

- `use-report-document.ts`: `DraftBlock.outcome`; маппер `test-editor.mappers.ts` — туда и
  обратно.
- `report-document-list.tsx`: стрелка раскрытия у системного блока, если вариант объявляет
  поля или настройки; метка «Разное содержимое по исходу» в `page-row__meta`.
- `report-block-fields.tsx`: переключатель «Разное содержимое при разном исходе»; три группы
  `tb-textgroup` с `tb-section-label`; длинный текст — свёрнутый вид `tb-feedback-preview` с
  карандашом, редактор — `FeedbackEditorModal` (как у вводного текста); у переопределённого
  короткого поля и настройки — сброс `rotate-ccw` в `tb-feedback-head__trail`; подпись
  «Печатается после текста «При любом исходе»» под длинным текстом исхода; у настройки исхода
  первый пункт «Как при любом исходе: …».
- Выключение при заданных значениях — окно подтверждения «Убрать содержимое по исходу?».
- Нет вердикта — переключатель недоступен с подписью из эскиза.
- Свёрнутый вид длинного текста — и для полей авторской страницы (эскиз согласован в этом
  виде).

**Тесты:** компонентные на каждое состояние эскиза; маппер.

## Решения до старта

Оба предложения приняты владельцем 2026-11-12.

1. **Какие поля стандартный шаблон объявляет у системных блоков.** Решение: «Заголовок
   блока» (`text`) и «Подводка» (`html`) у «Сводки баллов», «Результатов по темам», «Сводного
   разреза», «Шкал», «Показателей», «Рекомендаций», «Курсов», «Мероприятий». Пустой заголовок
   печатает нынешний заголовок блока, пустая подводка не печатается — документ теста, который
   ничего не трогал, не меняется. «Шапка» и «Вводный блок» — без полей: у вводного блока свои
   тексты по исходу в «Обратной связи».
2. **Настройка «Какие темы показывать».** В эскизе она пример настройки. Чтобы она работала,
   отбор тем должен делать продукт при построении контекста блока — это отдельная логика сверх
   механизма исхода. Решение: в этот трек не включать; механизм настроек по исходу
   делается целиком, а первые реальные настройки появятся отдельной задачей.
