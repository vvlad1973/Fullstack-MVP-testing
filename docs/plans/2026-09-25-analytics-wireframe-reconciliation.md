> **Для исполнителя:** задачи идут по этапам сверху вниз. Внутри этапа — по одной: падающий тест,
> правка, целевой прогон, коммит. Шаги отмечены чекбоксами (`- [ ]`). Задача, которая добавляет или
> меняет элемент интерфейса, начинается со сверки с эскизом; если элемента в эскизе нет, сначала
> дорабатывается эскиз и согласуется с владельцем, и только потом пишется React.

**Цель:** закрыть расхождения реализованного раздела «Аналитика» и страницы аналитики теста с
согласованными эскизами и с требованиями PRD-56 и PRD-66.

  [prd56-analytics-section.html](../wireframes/prd56-analytics-section.html),

`prd-66-psychometrics` влита в `main` целиком; ROADMAP ещё пишет «НЕ влита» (задача 0.1).

## Что нужно знать до начала

- **Vitest запускается ТОЛЬКО через npm:** `npm test -- <путь>`. Полный прогон — только с явного
  разрешения владельца.
- **`npm run check` бывает ложно-зелёным:** кэш `tsc` общий у worktree. Надёжная проверка —
  `npx tsc --noEmit --incremental false -p .`.
- **Дев-сервер без watch:** серверные правки видны только после перезапуска. Для приёмки поднимать
  свой экземпляр на свободном порту (`PORT=<порт> VITE_HMR_PORT=<порт> npm run dev`) и убеждаться
  по строке `serving on port N` в журнале.
- **Приёмка интерфейса — в браузере, обязательно.** Если MCP-браузер занят другой сессией, работает
  свой CDP-драйвер к `chrome-headless-shell`.
- **Дев-база общая.** Приёмка, которая пишет строки (импорт, снятие партии с учёта), делается на
  фикстуре `npm run psycho:demo` и убирается за собой (`npm run psycho:demo -- --drop`).

## Этап 1. Функциональные дефекты PRD-66

Числа на экране расходятся с тем, что выбрал автор, либо у требования нет интерфейса вовсе.
Идут первыми.

- [x] **1.1. Фильтр экрана не доходит до психометрики (FR-04a, FR-45, FR-54b).** *Закрыто
  2026-09-25:* условия экрана идут во все пять вызовов; принято в браузере на «PRD-66 демо:
  смешанный источник» — с «Источник: импорт» выборка 20 участников вместо 60, выгрузки с тем же
  условием. Условие исхода сервер психометрики не читает — как и сервер «Обзора». Запросы
  `/api/analytics/psychometrics/:testId`, `/items/:id`, `/scales` уходят без условий фильтра
  (`client/src/pages/author/test-analytics.tsx`, ключи запросов около строк 312, 356, 369), ссылки
  «Психометрический отчёт» и «Матрица ответов» — тоже (около 759-760). Сервер условия принимает
  (`server/routes/analytics/psychometrics.ts`, `readQuery`). Правка: тот же `filterSearch`, что у
  `/api/analytics/tests/:id`, в ключ и адрес всех пяти вызовов. Интерфейс не меняется.
  Тест: смена фильтра меняет адрес запроса психометрики и ссылок выгрузки.
- [x] **1.2. Переключатель «учитывать в расчётах» у партии импорта (FR-12).** *Закрыто

  снятой — подпись «не учитывается в расчётах — данные сохранены». Попутно найдено и исправлено:
  сброс кэша аналитики по ключу `["/api/analytics"]` не совпадал ни с одним запросом, и после
  импорта или переключения страница показывала прежние числа (общая функция
  `invalidateAnalytics`). Принято в браузере: снятие загрузки на демо-тесте уменьшило выборку
  импорта с 60 до 42 наблюдений без перезагрузки. Остаётся неудобство: список загрузок форма
  показывает только после выбора файла (задача 1.2a).
- [x] **1.2a. Список загрузок без выбора файла.** *Закрыто 2026-09-25:* на странице аналитики
  теста список загрузок с переключателем виден до выбора файла (дельта эскиза согласована). По
  решению владельца окно до выбора файла приведено к эскизу целиком: загрузчик, «Группа»,

  Осталось от эскиза: разделительной линии подвала окна нет — кнопки в теле формы, а не в
  `footer` окна.
- [x] **1.3. Переключатель «только первая попытка» (FR-51).** *Закрыто 2026-09-25:* чип
  «Только первая попытка» в строке фильтра на вкладках «Качество заданий» и «Вопросы», учтён в
