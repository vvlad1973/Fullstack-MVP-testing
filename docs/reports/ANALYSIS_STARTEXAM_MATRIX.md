## 1. Как читать таблицы

Условные обозначения в колонках продуктов:

- `+` — есть, заявлено или реализовано;
- `+/-` — есть частично, с существенной оговоркой (оговорка всегда в колонке «Комментарий»);
- `-` — нет; для StartExam означает «не заявлено на публичных страницах», а не доказанное отсутствие;
- `?` — публичных данных не найдено.

Колонка «Перевес» показывает, на чьей стороне строка: `SK` — Skill'Ум, `SE` — StartExam, `=` — паритет
или незначимая разница.

**Оговорки о достоверности.**

1. StartExam описан по публичным страницам вендора, документации интеграций (Teachbase) и обзорным
   каталогам. Демо-доступ не запрашивался, функции **не верифицированы**.
2. Источники расходятся в перечне типов заданий (см. [§4](#4-конструктор-и-типы-заданий)) и в цене
   платформы тестирования (см. [§14](#14-коммерческие-условия-и-внедрение)). Расхождения приведены как есть.
3. Skill'Ум описан по [README](../../README.md) и [ROADMAP](../ROADMAP.md). Треки со статусом «не начат»
   и «в работе» отмечены отдельно и **не засчитаны как имеющиеся функции**.
4. При актуализации 2026-09-17 сторона Skill'Ум сверялась по **журналу слияний в `main`**, а не по
   ROADMAP: карта отстаёт от кода (на дату сверки PRD-56 значился в ней «эскизов и кода нет» при
   влитых этапах Э1-Э6). Статус трека определяется наличием кода в стволе, а не шапкой документа.

### 4.1 Оформление содержимого задания

Это **не типы заданий**, а средства оформления текста вопроса. Дословная формулировка вендора:
«Поддерживаются изображения, формулы LaTeX и вставка кода, а также ветвление».

Разграничение, которое здесь важно: markdown — разметка **форматирования текста** (жирный, курсив,
ссылка), LaTeX — язык записи **математической нотации**, которая рендерится двумерно. Наличие первого
не закрывает потребность во втором.

| --- | --- | --- | --- | --- |
| Форматирование текста задания | + (подмножество markdown: жирный, курсив, ссылка, автоссылка на URL и email, переносы и абзацы) | ? (перечень не раскрыт) | У Skill'Ум одна реализация на оба хоста (`shared/text/markdown`), хранение — plain text, набор выходных тегов фиксирован. Нет списков, заголовков, таблиц, инлайн-кода | = |

### 4.2 Расхождение источников по перечню типов

Официальная страница платформы тестирования даёт перечень: «9 типов: одиночный и множественный выбор,
установление соответствия и последовательности, заполнение пропусков, открытый ответ (эссе), видео- и
аудиовопросы». Обзорный каталог перечисляет те же «девять» иначе: «сортировка, соответствие, текстовый
ввод, выбор одного/нескольких, оценка 360, видеоинтервью, шкала Ликерта, эссе» — то есть подмешивает
сюда механики соседних продуктов (оценка 360 и видеоинтервью — отдельные модули, а не типы заданий
конструктора). Достоверно только пересечение перечней; края — нет.

### 5.1 Адаптивный режим: что входит

Строка «адаптивная выдача» в редакции 2026-08-01 сворачивала в три слова целый режим. Развёрнуто,
поскольку это одна из немногих осей, где перевес не оспаривается ни одним из четырёх конкурентов.

| Составляющая | Skill'Ум | StartExam |
| --- | --- | --- |
| Единица адаптации | Блок заданий уровня внутри темы: `questionsCount` заданий, затем решение о переходе | - |
| Точка входа | Средний уровень темы, дальше маршрут строится по результату | - |
| Правило перехода | Порог уровня в процентах или абсолюте; вверх при достижении, вниз при недоборе | - |
| Полоса трудности уровня | Диапазон сложности `min`-`max`, из которого уровень набирает задания | - |
| Обратная связь на уровень | Свой текст на каждый уровень, а не один на тест | - |
| Учебные ресурсы на уровень | Ссылки с названием и адресом, привязанные к уровню: «не взял уровень — вот что почитать» | - |
| Итог прохождения | Достигнутый уровень по каждой теме плюс общий итог; отдельный тип отчёта `report.adaptive` | - |
| Журнал траектории | События `start` / `answer` / `level_up` / `level_down` / `topic_complete` / `test_complete` с отметками времени | - |
| Поправка на экспозицию | + (PRD-55, 2026-09-14): вес считается ВНУТРИ полосы трудности, поэтому горячее лёгкое задание не конкурирует со свежим трудным | - |
| Анализ уровней автору | + (PRD-56): статистика по уровням во вкладке «Выдача», траектория прохождения в реестре | - |

**Как это называть.** Наш режим — маршрутизация **блоками**, а не адаптация на уровне отдельного
задания: решение принимается по итогам блока уровня, модели ответа (IRT) нет. По отраслевой
классификации это ближе к MST, чем к CAT, и в материалах для заказчика словом «CAT» его называть
нельзя — см. [записку о мировой практике](./ANALYSIS_WORLD_BEST_PRACTICE.md) §5.

## 16. Что из этого следует

1. **Не сравнивать продукты «в лоб».** При прямом сравнении по чек-листу закупки StartExam выигрывает
   у Skill'Ум по числу закрытых пунктов, потому что закрывает более широкую задачу. Сравнение выгодно
   Skill'Ум только в рамке «нужен тест внутри нашей LMS и нашего контура».
2. **Три пробела определяют, попадаем ли мы в сделку вообще:** SSO, прокторинг (через интеграцию,
   не своими силами), открытые задания. Ни один из них не про методику — все три про допуск к столу
   переговоров. Формулы LaTeX и листинг кода в этот список не входят: они ограничивают отраслевую
   применимость (инженерные, финансовые, ИТ-аттестации), но сделку не отсекают, и стоят несопоставимо
   дешевле первых трёх.
3. **Два пробела определяют, можем ли мы вообще участвовать в тендере:** отсутствие аттестата ИБ и
   отсутствие реализованного экрана согласия на обработку данных. Второй уже признан техдолгом.
4. **Отстраиваться следует по трём точкам, где конкурент публично уязвим:** цена входа, отчётность,
   устаревший интерфейс тестирования — всё это фигурирует в отзывах о StartExam. По второй точке
   за полтора месяца пройден целый трек (PRD-56), и её стоит перевести из «потенциала» в аргумент.
5. **Единственный обгоняющий, а не догоняющий трек — психометрика.** У StartExam заявлена «аналитика
   качества заданий» без раскрытия глубины; закрытый BRD по CTT, надёжности и анализу дистракторов дал бы
   Skill'Ум аргумент, которого нет ни у одного из рассмотренных конкурентов. Канал данных под неё
   построен попутно: импорт наблюдений (PRD-54), время на задании, экспозиция, согласованность шкал.
6. **Вывод 2 не изменился, а вывод про аналитику изменился.** Из трёх допускных пробелов не закрыт
   ни один: SSO, прокторинг и открытые задания стоят там же, где стояли 2026-08-01. Всё, что влито
   за полтора месяца, углубляло сильные стороны, а не закрывало отсечки. Это осознанный выбор или
   инерция бэклога — вопрос к владельцу продукта, но в следующей редакции он должен быть отвечен.
